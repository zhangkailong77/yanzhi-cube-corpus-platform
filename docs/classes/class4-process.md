# 第四类别：业务流程与规则类

## 类别说明

**定义**：将真实业务流程、规则、判断逻辑做成可复用语料对

**目标**：构建企业级可复用的业务规则库，支持AI助手、业务自动化、合规风控等应用

**典型用途**：
- 企业内部AI助手
- 跨境业务自动化
- 合规/风控问答

---

## JSON格式定义

### 文件命名规范
```
process_{语言代码}.json

语言代码：
- zh: 中文
- en: 英语
- th: 泰语
- ms: 马来语
- vi: 越南语
```

### JSON结构模板

```json
{
  "meta": {
    "version": "1.0",
    "corpus_type": "process",
    "language": "zh",
    "domain": "trade",
    "created_by": "专家团队",
    "created_at": "2024-01-15T10:00:00Z",
    "description": "业务流程与规则库 - 中文"
  },
  "data": [
    {
      "rule_id": "RULE-001",
      "scenario": "客户申请跨境退货",
      "condition": "商品已清关且非质量问题",
      "result": "不支持无理由退货",
      "category": "退货政策"
    }
  ]
}
```

---

## 字段说明

### 顶层 meta 字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `version` | string | 是 | 版本号（如：1.0） |
| `corpus_type` | string | 是 | 语料类型（固定值：process） |
| `language` | string | 是 | 语言代码（zh/en/th/ms/vi） |
| `domain` | string | 是 | 业务域（trade/customs/payment/logistics等） |
| `created_by` | string | 是 | 创建者/团队 |
| `created_at` | string | 是 | 创建时间（ISO 8601格式） |
| `description` | string | 是 | 语料描述 |

### 规则记录字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `rule_id` | string | 是 | 规则唯一标识符（如：RULE-001） |
| `scenario` | string | 是 | 业务场景描述 |
| `condition` | string | 是 | 判断条件（自然语言描述） |
| `result` | string | 是 | 规则结果/动作 |
| `category` | string | 否 | 规则分类（便于管理） |

---

## 规则分类标准

### category 字段的可选值

```
1. 退货政策：跨境退货、无理由退货、质量问题退货、清关后退货等
2. 支付规则：定金比例、支付方式选择、信用审查、大额订单支付等
3. 海关规则：许可证要求、归类规则、原产地要求、监控商品管理等
4. 物流规则：包装要求、运输方式选择、保险要求、特殊货物处理等
5. 风控规则：新客户订单、大额订单、敏感地区、信用评级要求等
6. 合规规则：出口管制、制裁清单、最终用户审查、敏感技术出口等
7. 合同规则：验收条款、违约责任、争议解决、合同变更等
8. 其他：其他业务规则
```

## 多语生成策略

### 源语言策略
- **源语言**：中文
- **语料来源**：专家编写的200条业务规则
- **质量保证**：由业务专家审核，确保规则准确性

### 翻译策略

#### 1. 翻译方式
- **英语**：AI翻译 + 人工校对（建议抽检20%）
- **泰语**：AI翻译 + 人工校对（建议抽检30%）
- **马来语**：AI翻译 + 人工校对（建议抽检30%）
- **越南语**：AI翻译 + 人工校对（建议抽检30%）

#### 2. rule_id保持一致
- 所有语言的规则保持相同的`rule_id`（如RULE-001、RULE-002等）
- 便于跨语言查询同一规则
- 便于多语言AI助手使用

#### 3. 翻译Prompt模板
```
作为跨境贸易专家，请将以下中文业务规则翻译为[目标语言]。

要求：
1. 准确翻译专业术语（参考术语库）
2. 保持规则逻辑一致
3. 条件表达清晰、准确
4. 结果描述具体、可执行
5. 表达地道、专业

中文规则：
{
  "rule_id": "RULE-XXX",
  "scenario": "[场景描述]",
  "condition": "[条件描述]",
  "result": "[结果描述]",
  "category": "[规则分类]"
}

请返回目标语言的JSON格式。
```

### 翻译质量控制

#### 1. 专业术语翻译一致性
- 使用第一类别"术语与标准表达类"的术语库
- 关键术语（如HS编码、L/C、清关等）保持一致性
- 缩写术语保留英文（如L/C、DDP等）

#### 2. 规则逻辑保持一致
- `scenario`、`condition`、`result`三者逻辑关系保持一致
- 条件表达清晰，不产生歧义
- 结果描述具体、可执行

#### 3. 人工抽检标准
- **英语**：抽检20%，重点关注术语准确性和逻辑一致性
- **泰语/马来语/越南语**：抽检30%，重点关注语法、词汇准确性
- 抽检记录：记录抽检结果，用于后续AI模型优化

## 与其他类别的关联

### 与第一类别（术语类）的关联
- **术语一致性**：规则中的术语与术语库保持一致
- **翻译参考**：使用术语库的translations作为翻译参考

### 与第二类别（问答类）的关联
- **规则问答化**：可以将规则扩展为问答形式
- **场景复用**：问答中的场景可以提取为规则

### 跨类别复用示例

#### 从问答类提取规则
```
问答库 QA-004（中文）:
  ├── question: "如何避免HS编码申报错误？"
  └── answer: "避免HS编码申报错误的措施包括：1）准确了解货物属性...；2）建立复核机制..."

规则库 RULE-003（中文）:
  ├── scenario: "进口货物申报"
  ├── condition: "HS编码属于监控商品且价值超过5000美元"
  └── result: "必须提供自动进口许可证"
```

#### 从术语库提取规则
```
术语库 TERM-003: HS编码
  └── definition: 商品名称及编码协调制度的简称...

规则库 RULE-010（中文）:
  ├── scenario: "商品归类"
  ├── condition: "HS编码不明确或存在争议"
  └── result: "向海关申请归类预裁定"
```

## 数据验证规则

### 通用验证规则
1. **JSON格式验证**：文件必须是有效的JSON格式
2. **字段类型验证**：所有字段类型必须符合定义
3. **必填字段验证**：必填字段不能为空或null
4. **唯一性验证**：rule_id必须在文件内唯一
5. **枚举值验证**：category等字段必须在定义的范围内
6. **格式验证**：日期、时间等格式必须正确（如created_at使用ISO 8601格式）

### 规则特定验证规则
1. **rule_id格式**：必须符合 RULE-XXX 的格式（XXX为数字）
2. **scenario长度**：场景描述不能少于10个字符
3. **condition长度**：条件描述不能少于10个字符
4. **result长度**：结果描述不能少于10个字符
5. **category枚举**：必须在预定义的规则分类范围内

---

## 注意事项

1. **rule_id命名**：必须保持跨语言一致，便于多语言AI助手使用
2. **condition表达**：使用自然语言描述，简洁清晰，避免歧义
3. **术语一致性**：规则中的术语与术语库保持一致
4. **规则逻辑**：scenario、condition、result三者逻辑关系要清晰
5. **category分类**：建议使用预定义的8大类规则分类
6. **结果可执行**：result字段描述要具体、可执行
7. **场景覆盖**：尽可能覆盖主要业务场景，提高复用性
8. **人工校对**：英语20%，其他语言30%，确保翻译质量
9. **跨类别复用**：可从问答类、术语类提取规则，提高效率
10. **企业级应用**：规则设计要考虑企业级AI助手、业务自动化等实际应用场景

## 规则设计建议

### 1. 场景描述（scenario）
- 明确触发场景
- 使用业务术语
- 描述具体、清晰

**好的示例**：
- "客户申请跨境退货" ✅
- "大额订单支付" ✅

**不好的示例**：
- "退货" ❌（不够具体）
- "付款" ❌（不够具体）

### 2. 条件描述（condition）
- 使用自然语言
- 条件明确、无歧义
- 支持多条件组合（使用"且"、"或"）

**好的示例**：
- "商品已清关且非质量问题" ✅
- "HS编码属于监控商品且价值超过5000美元" ✅

**不好的示例**：
- "清关了" ❌（不够具体）
- "金额大" ❌（不明确）

### 3. 结果描述（result）
- 结果具体、可执行
- 描述清晰、无歧义
- 符合业务规范

**好的示例**：
- "不支持无理由退货" ✅
- "必须提供自动进口许可证" ✅

**不好的示例**：
- "不行" ❌（不够具体）
- "看看" ❌（不明确）

## 优势总结

### 1. 结构简洁
- 仅5个字段（4个必填 + 1个可选）
- 场景 → 条件 → 结果，逻辑清晰
- 易于理解和维护

### 2. 应用场景广
- 企业内部AI助手
- 跨境业务自动化
- 合规/风控问答
- 客户服务支持

### 3. 复用性强
- 规则可跨场景复用
- 可扩展为问答形式
- 可与其他类别关联

### 4. 多语言支持
- rule_id保持一致
- 便于多语言AI助手
- 支持跨境业务应用

## 企业级应用示例

### 应用场景1：AI助手问答
```
用户问题：我的货已经清关了，但我不想买了，可以退货吗？

系统查询：
1. 场景匹配：客户申请跨境退货
2. 条件匹配：商品已清关且非质量问题
3. 结果返回：不支持无理由退货

系统回答：根据退货政策，商品已清关且非质量问题的，不支持无理由退货。
```

### 应用场景2：业务自动化
```
触发条件：订单金额超过100,000美元

系统查询：
1. 场景匹配：大额订单支付
2. 条件匹配：订单金额超过100,000美元
3. 结果执行：建议使用信用证（L/C）支付方式

系统动作：自动向客户推荐信用证支付方式，并提供开户指引
```

### 应用场景3：合规风控
```
触发条件：商品属于出口管制清单且目的地为敏感国家

系统查询：
1. 场景匹配：出口管制商品
2. 条件匹配：商品属于出口管制清单且目的地为敏感国家
3. 结果执行：需要申请出口许可证并进行最终用户审查

系统动作：自动触发合规审查流程，提醒业务人员申请许可证
```
